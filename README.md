# 加油站班次交接 · 复核账

交接单与罐存读数接成一本**复核账**，解决交接员断网补录、早班同步后罐存与收入被算乱的问题。

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 数据默认保存在浏览器 localStorage；`src/engine/` 为纯逻辑层（模拟服务端 + 重算引擎），可直接替换成真实接口。

## 核心规则

1. **重复补录只算一次**
   - 自然键 `日期#班次` 唯一；同一班次只允许一张交接单参与计算。
   - 每张单首次提交生成客户端 `txnId`，服务端按事务号幂等：断网重试、刷新后续传都不会产生第二笔。
2. **现金/电子支付或罐存读数变化 → 只重算受影响班次，其他班次保留上次结果**
   - 重算引擎 `src/engine/reconcile.ts` 为每个班次缓存两个签名：
     - `ownSig`：本班现金、电子支付、泵码/罐存读数；
     - `baselineSig`：上一复核通过班次的各品结束罐存读数。
   - 改现金/电子支付：只有本班重算；改上游通过班次的结束读数：本班与其后沿链班次重算；
     两个签名都没变的班次标记“保留上次结果”。
3. **列表先标待复核**
   - 待复核/驳回排在列表前面，高亮显示；只有罐存链上的下一张未通过单允许“复核通过”，驳回单会阻断链。
4. **复核通过前不计入**
   - 待复核/驳回班次的收入不进累计总收入、泵码销量不进通过销量；
   - 起始罐存只接续最近一张紧邻的“复核通过”单，中间有未通过单则标“链断开、起始罐存暂不接续”。
5. **两名值班员同时提交同一交接单**
   - 乐观锁（`version`）：后到者收到冲突弹窗，自己的输入完整保留，左右对比后选择
     “保留我的输入并覆盖”（对齐版本后原子提交）或“采用先到者”（回填表单）。
6. **写入失败从断点继续，不留半套数字**
   - 模拟服务端 `src/engine/server.ts` 使用 WAL（预写日志）：先写 WAL → 落库 → 清 WAL；
     中途“断电”（页面顶部可模拟）后，下次提交或启动时从 WAL 重放，重放本身幂等（版本不会 +2）。
   - 客户端断网箱 outbox 持久化失败/发送中的写入，联网后 FIFO 自动续传，状态在“断网箱”面板可见。
7. **离线补录**
   - 断网时录入的交接单以“本地待同步”影子单立即显示为待复核，联网落库后自动替换为服务端记录。

## 差异口径

- 收入 = 现金 + 电子支付（通过后才计入累计）。
- 泵码销量 = 泵码止 − 起；罐存销量 = 起始罐存 + 配送 − 结束罐存。
- 量罐差异 = 罐存销量 − 泵码销量（正溢余、负损耗，超 20L 标红）。
- 收款差异 = 现金 + 电子 − Σ(泵码销量 × 指导价，按品取整)（正长款、负短款，超 10 元标红）。

## 演示数据

账期 2026-10-03 至 10-05 共 7 个班次：前 4 张已复核，后 3 张为断网补录待复核；
10-04 早班埋了 80 元短款，10-04 晚班 92# 埋了 100L 量罐差异，方便观察重算与阻断效果。

## 可试的操作路径

1. 打开“模拟断网”，补录一个班次 → 进入断网箱、列表出现本地待复核单；恢复网络自动续传。
2. 开启“下次写入中断”再提交 → 提示 WAL 断点；刷新页面后启动自动续传，数字完整。
3. 填好表单点“模拟同事先提交”，再保存 → 出现冲突弹窗，体验后到者二选一。
4. 对已复核班点“修订”改现金 → 只有该班重算；改结束罐存 → 下游班也重算；已复核单改数字会退回待复核。
