# 加油站班次交接 · 罐存复核账

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Element Plus、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 自检：`npm test`（复核账规则端到端 + SSR 冒烟）

数据保存在浏览器 localStorage（`dfwlfront-7-ledger-v2`），后续可把仓储层替换为接口。

## 业务规则怎么落地

交接员断网时会补录交接单，早班同步后罐存和收入不能被算乱。系统把交接单和罐存读数接成**复核账**：

1. **重复补录只算一次**：每张交接单带幂等键（补录终端生成），仓储层 upsert 去重；
   相同幂等键再次提交直接返回「重复」，不覆盖原值。
2. **只重算受影响班次，其他班次保留上次结果**：引擎对每行按
   「本班现金/电子支付/流量/罐存读数 + 上游罐存与读数锚点」生成签名；
   - 现金/电子支付变化：只重算本行（收入差异变，罐存链不动）；
   - 罐存实测读数变化：本行与紧邻下一班重算（下一班起始罐存=本班实测）；
   - 流量读数变化：本行销量与下一班读数衔接重算；
   - 其他油品、其他班次签名不变，直接复用上次结果，列表中标注「保留上次结果」。
3. **列表先标待复核**：新单一律 `pending`。
4. **复核通过前不计入正式账**：
   - 正式账只串已复核单据，待复核班的销量不进正式总收入、不作为正式起始罐存传递；
   - 工作账（含待复核）连续推算，用于早班同步前先看差异；
   - 顶部指标与油品卡片把「已复核 / 待复核」两口径分开列示。

## 并发与故障语义

- **两名值班员同时提交同一交接单**（同 油品+日期+班次 槽位）：先来者入账不动，
  **后到者的输入原样保留**在冲突面板并看到冲突明细；由后到者选择「覆盖」（乐观锁版本号 +1）
  或「放弃」。
- **写入分两步，绝不留半套数字**：
  1. 入队：操作写入 outbox 并落盘；tmp 没写成则本次等于未发生，可整张重交；
  2. 应用：在同一快照里完成「改数据 + 出队」，经 `tmp → 正式指针` 原子切换。
- **写入失败后从断点继续**：tmp 已完整落盘会被提升为正式快照（该步视为完成），
  未完成的操作留在 outbox，点「从断点继续」重做，幂等保证不产生两遍数；
  崩溃在指针切换前，重启时以较新 tmp 为准恢复。
- 多标签页通过 `storage` 事件自动同步并重建行缓存。

## 演示工具

补录表单右上角两个故障注入按钮，可分别模拟：
- 「写入中断（有断点）」：tmp 落盘后失败 → 顶部出现断点横幅，点「从断点继续」补齐；
- 「存储不可用」：tmp 写前失败 → 提示可直接重试。

## 目录

- `src/domain/types.ts` — 交接单/复核账类型
- `src/domain/ledger.ts` — 双账（工作账/正式账）+ 行级签名缓存的纯函数引擎
- `src/store/handoverStore.ts` — 幂等去重、冲突乐观锁、outbox、tmp 原子提交、恢复
- `src/App.vue` — 补录、冲突裁决、复核、断点续传界面
- `scripts/test-ledger.ts` — 规则端到端自检（内存 localStorage 垫片）
